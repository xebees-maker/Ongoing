== 2026-06-17 작업 요약 ==

[ 오늘 삽질한 것들 ]

1. GPIO 핀 오정보
   - 웹 비공식 소스에 "배터리 ADC = GPIO1"이라는 잘못된 정보가 퍼져 있었음
   - 여러 AI 모델이 이걸 학습해서 GPIO1이라고 계속 알려줌
   - GPIO1에서 ADC raw=4095 (포화) / 0V 왔다 갔다 → floating 핀이었음
   - 실제 회로도 핀 테이블(노란 하이라이트)에는 IO12 = BAT_ADC 로 명확히 표기
   → 정답: GPIO12 (ADC2_CH1)

2. VBAT_DIV 값 헤매기
   - 잘못된 GPIO로 측정하다 보니 분압비도 계속 틀렸음
   - 11.0 → 1.44 → 1.73 → 3.0 순서로 틀리다가 GPIO 고치고 나서야 3.0 확정
   - R19=200K (상단), R21=100K (하단) → 중점 = VBAT × (100/300) = VBAT/3
   - 실측: vADC 1355mV, VBAT 이론값 1357mV → 오차 0.1% → 완벽히 맞음

3. 게이지가 아예 안 갱신되던 문제
   - 처음에 BAT_GAUGE_EVERY=600 (10분)으로 설정해서 1시간 기다려도 안 됐음
   - 워치독 리셋이 중간에 끼어들어 카운터 n이 계속 리셋됨
   - 배터리 뺐다 껴도 n이 유지되는 것 보고 워치독 리셋이 원인임을 파악

4. ADC2 캘리브레이션 크래시
   - GPIO12로 옮기면서 ADC2로 전환하자 첫 시도에서 워치독 리셋 발생
   - 일시적으로 캘리브레이션 비활성화 후 안정화 확인, 재활성화 → 문제없음

5. 배터리 잔량이 혼자 오르던 문제
   - ADC 노이즈 때문에 peak 기반 측정에서 순간 높은 값이 찍히면 peak 갱신
   - 배터리 방전 중인데 % 증가하는 현상 발생
   → 이동평균(11샘플 순환버퍼)으로 전환해서 해결

6. USB 즉시 갱신 안 되던 문제 (여러 단계 삽질)
   - bat_sample_cb 1초 타이머에서 USB 상태 변화 감지 → bat_gauge_refresh() 호출
     구조 자체는 맞았는데 동작 안 함
   - 원인 분석: bat_display_update()가 N=10 틱에서 "이전 값으로 먼저 갱신,
     그 다음 bat_gauge_refresh()로 새 값 계산" 순서로 돌고 있었음
     → 표시 먼저, 계산 나중 = 항상 한 박자 늦음
   - 또한 N=10 틱에서 bat_display_update(old_pct)와 bat_gauge_refresh()가
     같은 틱에 둘 다 실행돼서 구 값이 반짝 표시된 후 새 값이 표시되는 구조
   → 수정: N=10에서는 bat_gauge_refresh()만 실행하고 return,
           N<10에서만 bat_display_update(s_last_pct)로 아이콘 갱신

7. 화면 자동 꺼짐 기능 추가 후 게이지 0% 표시
   - 화면 꺼짐 기능과 같은 시점에 VBAT_DIV를 3.0 → 2.0으로 잘못 바꿔놨던 게 원인
   - "실측: 2790mV/1408mV=1.98"이라는 새 측정치를 근거로 바꿨는데, 이전에
     이미 검증된 3.0(R19=200K/R21=100K)이 맞는 값이었음 → 잘못된 재측정이었던 것
   → VBAT_DIV는 3.0으로 유지, 절대 2.0으로 바꾸지 말 것

8. 장치(B)가 USB 뽑으면 완전히 꺼지는 문제 (가장 오래 삽질)
   - 처음엔 "화면 자동 꺼짐" 기능이 화면만 끄는 거라 오해한 줄 알았는데,
     사용자가 빨간 전원 LED까지 꺼지고 터치 무반응이라고 확인 → 진짜 전원 차단
   - 리셋/크래시 후 GPIO14 재설정 실패 이론으로 접근했으나, 사용자가
     "어제 장치(A)는 USB 뽑아도 리셋 자체가 안 일어난다"고 반박 → 가설 폐기
   - 같은 빌드(1502d59, 무수정)를 A/B 양쪽에 똑같이 플래시해서 비교
     → A는 정상(배터리만으로 57% 동작), B는 여전히 사망
   - 멀티미터로 B 측정: 배터리 전압 정상 인가, GPIO14(Q1 게이트)=0V(정상)
   → 소프트웨어가 완전히 동일한데도 증상이 다르므로 B의 하드웨어(Q1/AO3401
     또는 그 납땜) 불량으로 결론. 코드 문제 아니었음.

4. 게이지 갱신 순서 버그 발견 및 수정
   - N=10 틱의 표시/계산 순서 역전 문제를 구조적으로 해결
   - N=10: bat_gauge_refresh() 단독 실행
   - N<10: bat_display_update(s_last_pct)로 아이콘만 매초 갱신

5. 최종 게이지 타이밍 구조
   - 첫 샘플 → 즉시 초기값 표시
   - USB 상태 변경 → 즉시 재계산
   - 10초마다 → 이동평균 재계산
   - 매초 → 충전 아이콘/색상만 갱신

6. 화면 자동 꺼짐/켜짐 기능 구현
   - bsp_indev_set_hook()로 BSP 터치 콜백에 전역 인터셉터 추가
   - ui_input.c: global → active-tab 우선순위 디스패처
   - ui_screen.c: USB 연결 중 항상 ON, 배터리 모드 10초 무터치 → OFF, 터치 시 ON
   - VBAT_DIV/LittleFS 등 다른 변경은 빼고 이 기능만 정상 장치(A, COM9)에 적용

7. 동일 빌드 A/B 비교로 코드 vs 하드웨어 문제 명확히 분리
   - "같은 펌웨어를 두 장치에 똑같이 플래시했는데 증상이 다르면 하드웨어 문제"
     라는 진단법으로 B의 전원 경로(Q1) 하드웨어 불량을 확정
   - 커밋 dbc5d12로 화면 자동 꺼짐 기능 반영, origin push 완료

8. DHT22 %f 포맷 버그
   - 화면에 숫자 대신 "f °C"만 찍힘
   - 원인: LVGL이 LV_USE_BUILTIN_SPRINTF(경량 sprintf)를 쓰는데 %f(부동소수점) 미지원
   - 정수 연산(temp*10 → 정수 변환 → /10, %10)으로 직접 포맷해서 해결
   → 앞으로 LVGL 라벨에 소수 표시할 때 %f 쓰지 말 것

9. SCD41 I2C 통신 디버깅 (미해결, 보류)
   - 처음 같은 버스(터치와 공유)에 연결 → 통신 시도하자 터치까지 깨짐 → 전용
     버스(I2C_NUM_1, SDA=GPIO4, SCL=GPIO3)로 분리
   - start_periodic_measurement 계속 실패 → SCD41이 슬립 지원 모델이라 wake_up
     (0x36F6) 명령을 먼저 보내야 했던 게 원인 중 하나, 추가 후 start는 성공
   - 그런데 측정이 실제로 시작된 이후 get_data_ready_status가 매번 NACK
     (ESP_ERR_INVALID_RESPONSE) — 명령 대기 중엔 정상, 측정 중에만 깨짐
   - 모듈에 풀업(R1/R2)+캐패시터(C1) 내장 확인, VBAT→VBUS로 전원도 옮겨봤지만
     동일 증상 → SCD41이 광음향 측정 시 끄는 전류 스파이크(~200mA대)를 모듈의
     작은 C1이 못 받쳐주는 것으로 추정
   - i2c_master_bus_reset()으로 버스 행(hang) 복구 로직 추가
   → 결론: 코드는 정상, 하드웨어(전원 디커플링 부족)로 판단. 100~470uF 벌크
     캐패시터로 테스트 예정, 캐패시터 없어서 보류
