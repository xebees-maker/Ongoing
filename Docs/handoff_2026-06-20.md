## 1. Sens: VBUS 직접 감지 구현 (완료)

기존엔 `usb_serial_jtag_is_connected()`(데이터선 없는 단순 충전기는 못 잡음) +
전압-추세 추정(`battery_trend_is_powered()`, 정상 방전도 평탄해서 오판하던
결함 있는 보완 로직)으로 USB 연결 여부를 짐작하고 있었음. 오늘 하드웨어로
직접 VBUS를 측정하는 방식으로 교체 완료.

### 핀 선정 — 두 번 틀리고 세 번째에 확정
H1 헤더에 노출된 GPIO 1~9 중 외부 분배기를 물려도 안전한 핀(보드 풀업 없음,
펌웨어에서도 안 씀)을 찾아야 했음.

| 핀 | 결과 |
|---|---|
| IO1, IO2, IO3, IO4 | SD카드 SPI / LCD I2C 공유 + 보드 풀업(R3~R6, 10K→3V3) — 못 씀 |
| IO5 (`IMU_INT1`) | 온보드 QMI8658 IMU와 net 공유하지만 펌웨어에 IMU 드라이버 없음 — **이 핀 사용** |
| IO6 (`IMU_INT2`) | `SCD41_SDA_PIN`으로 이미 사용 중 |
| IO7 | `SCD41_SCL_PIN`으로 이미 사용 중 |
| IO8 | `DHT22_PIN`으로 이미 사용 중 |
| IO9 | BOOT 버튼, 사용 불가 |

처음 IO3을 추천했다가 풀업 간섭으로 전압이 틀어졌고(실측 USB 3.1V/배터리
2.7V, 계산해보니 R6 10kΩ 풀업 영향과 거의 정확히 일치), 다음으로 IO7을
추천했다가 이미 SCD41_SCL로 쓰이는 핀이라 또 틀렸음. IO5로 확정 전, 전원
OFF 상태에서 IO5-GND 저항이 무한대(플로팅)인지 먼저 확인한 후 배선.

### 최종 회로/측정값
- 분배기: H1 VBUS(1번 핀) → 100kΩ → IO5 → 100kΩ → GND (1:1 분배)
- 실측: USB 연결 시 IO5 ≈ 2.3V, 배터리 단독 시 IO5 ≈ 0V

### 코드 변경
- `Common/components/battery_monitor/battery.c`, `include/battery.h`:
  `battery_get_adc_handle()` 추가 — `battery_init()`이 만든 `ADC_UNIT_1` 핸들을
  그대로 돌려줘서, 새 ADC 유닛을 또 만들지 않고 같은 유닛에 VBUS용 채널만
  추가 설정할 수 있게 함. Cntl도 이 컴포넌트를 쓰지만 호출 안 하면 영향 없음.
- `Sens/main/sensor-c6.c`:
  - `vbus_is_present()` 추가 — `ADC_CHANNEL_5`(GPIO5) 읽어서 1200mV 임계값으로 판단
  - 기존 `battery_is_usb_connected()` 호출과 `battery_trend_is_powered()` 함수
    전체(USB 추정용 추세 버퍼/로직) 제거. 완충전압 학습용 추세 버퍼(`s_batt_trend`,
    별도 목적 — 평탄 구간 감지로 배터리 완충전압 캘리브레이션)는 그대로 유지
  - `screen_timer_cb`, `sample_cb` 모두 `vbus_is_present()`로 교체
- **빌드 미검증** — 이 세션 환경에 ESP-IDF가 PATH에 없어서 `idf.py build`를
  못 돌려봄. 다음 세션에서 IDF 터미널로 빌드 확인 필요, 빌드되면 실기
  플래시 + 데이터선 없는 충전기로 화면 안 꺼지는지 실제 검증 필요.
