한 장 요약

차폐 공간도, 배선이 어려운 현장도 무선으로.
관리는 편하고, 장애에 강하며, 정확하면서도 비용은 낮습니다.

1. 선 없는 설치, 관리가 편한 전원

충전 배터리와 USB 충전기 두 가지 전원으로 선을 늘어뜨리지 않고, 필요한 순간에만 깨어나 충전 주기가 깁니다. 모든 장치의 배터리 잔량을 한곳에 모아 원격으로 확인합니다.

11, 12쪽

2. 장애에 강한 통신

무선이 끊기거나 느려져도 스스로 복구해 명령과 데이터를 끝까지 전달하는 장애 감내(fault tolerance) 설계입니다.

8~10쪽

3. 유연한 확장과 재사용

무선 채널과 센서를 필요한 만큼 더하고, 장비를 바꿔도 기록은 이어집니다.

6, 14, 21쪽

4. 쉬운 사용과 원격 지원

현장 터치 화면과 휴대폰 웹앱으로 측정치와 현장 사진을 언제 어디서나 확인하고 조치합니다.

13, 19, 20쪽

5. 이중삼중의 장애 대응

통신이 끊기거나 저장 장치가 고장 나도 설비와 기록을 지키고, 문제는 에러코드로 알립니다.

16~18쪽

6. 다양한 제어 방식

강제, 타이머, 센서 AI, 센서 수동 가운데 현장에 맞는 방식을 고릅니다.

15쪽

7. 정확한 측정과 AI 생육 판단

고정밀 센서를 오차가 가장 적은 방식으로 측정합니다. 사진으로 생육을 판단하는 AI도 개발 중입니다.

12, 13쪽

8. 낮은 도입비와 운영비

검증된 범용 장비로 구성해 설치 공사와 유지 보수 비용을 줄입니다.

4, 7쪽

범용 IoT 장비로 유연한 구성을 만드는 네 가지 설계 원칙

전용 장비를 새로 만들지 않고 대량 생산으로 검증된 범용 IoT 장비를 조합해, 안정성을 높이고 개발 기간과 비용, 부품 수급과 교체 부담을 줄입니다.

1판단은 컨트롤러 한 곳에서

기록, 그래프, 알림, 제어 판단을 컨트롤러가 맡습니다. 노드는 측정과 통신에 집중하므로 작고 단순하게 유지됩니다.

2통신과 응용을 계층으로 분리

무선 구간의 재전송은 브리지에서 끝냅니다. 컨트롤러는 Wi-Fi와 CAN만 다루고 응용 메시지에 집중합니다.

3보드가 아니라 측정 항목 중심

사람이 보는 단위는 ‘무엇을 재는가’입니다. 보드와 센서가 바뀌어도 기록과 설정은 측정 항목에 남습니다.

4고장을 전제로 설계

일시적 실패는 재시도로 복구하고, 멈춤은 다른 장치가 감지합니다. 복구하지 못하면 원인을 코드와 경과로 남깁니다.

전체 구성: 측정부터 제어와 원격 확인까지

잡음에 강하고 여러 장치를 한 선으로 잇는 CAN에 브리지를 연결해 여러 무선 공간을 지원하므로, 차폐벽을 넘는 것은 안테나 선 하나뿐입니다(재배사 설치 예).

한 대의 IoT 장비가 여러 무선 채널을 맡습니다: 브리지

브리지는 무선 통신만 전담하는 작은 IoT 장비입니다. CAN에 이어 붙이는 만큼 무선 채널이 늘어납니다.

무선은 브리지가 전담

노드와의 무선, 재전송, 사진 조각 정렬을 브리지가 맡습니다. 컨트롤러는 판단과 화면에 집중합니다.

CAN으로 쉽게 늘림

한 선에 여러 장치를 잇는 CAN이므로, 공간이 늘면 브리지를 더 이어 붙이면 됩니다.

브리지마다 다른 채널

컨트롤러가 공유기 채널을 기준으로 서로 먼 채널을 정해 줍니다. 혼선에 강하고 채널 운영이 쉽습니다.

활용 예: 차폐벽 넘기

방식 A: 브리지 안테나가 벽 안으로

브리지 본체는 바깥에 두고, 안테나 선만 벽 안으로 넣어 안쪽 노드를 담당합니다. 습한 공간에는 무선 노드만 남습니다.

방식 B: 장치 안테나가 벽 밖으로

원격 제어기는 설비 옆에 두고, 외장 안테나 선을 벽 밖으로 빼서 바깥 브리지와 통신합니다.

노드는 자기 공간을 담당하는 브리지에만 응답하므로, 약한 신호로 엉뚱한 브리지에 붙지 않습니다. 고온을 견디는 장치는 별도 설계로 제작하여 공급합니다.

검증된 범용 IoT 장비로 구성해, 안정적이고 유지 보수가 쉽습니다

전용 칩이나 전용 무선 모듈 없이, 역할에 맞는 ESP32 계열 보드를 조합합니다.

검증된 부품으로 안정적

대량 생산되어 널리 쓰이는 모듈이라 안정적이고, 공급이 꾸준합니다.

쉬운 수리

고장 나면 같은 보드로 바꿉니다. 기록과 설정은 측정 항목에 남아 그대로 이어집니다.

낮은 운영 비용

보드 단가와 예비품 비용이 낮아 유지 보수 부담이 적습니다.

구간마다 성격에 맞는 통신을 씁니다

저전력 무선, 신뢰성 높은 유선, 범용 인터넷 접속을 역할별로 나눕니다.

노드 ↔ 브리지

ESP-NOW

2.4GHz 무선입니다. 접속 절차가 가벼워 짧게 깨어나는 노드에 알맞습니다.

브리지 ↔ 컨트롤러

CAN

긴 메시지는 표준 방식(ISO-TP)으로 나눠 보냅니다. 브리지를 한 선에 이어 붙입니다.

컨트롤러 ↔ 원격

Wi-Fi · WAN

웹앱의 실시간 갱신과 휴대폰 알림에 씁니다.

제어가 데이터보다 먼저

브리지마다 제어용과 데이터용 통로를 나누고 제어에 우선순위를 줍니다. 사진처럼 큰 데이터를 보내는 중에도 명령이 먼저 지나갑니다.

컨트롤러의 무선 부담 제거

컨트롤러는 Wi-Fi만 쓰고, 노드 무선은 브리지가 맡습니다. 화면과 기록에 쓸 메모리를 확보합니다.

저전력

노드는 가벼운 무선으로 짧게 깨어 보내고 바로 잠듭니다.

통신 안정성

잡음에 강한 유선과 응답 확인, 재전송으로 메시지를 지킵니다.

작은 메모리로 동작

긴 메시지는 나눠 보내고, 무선 처리는 브리지에 맡깁니다.

무선이 느려도 전체 통신은 멈추지 않습니다

느린 무선 구간의 기다림은 브리지가 맡고, 컨트롤러와 브리지 사이는 빠른 CAN으로 결과만 주고받습니다.
1. 요청컨트롤러가 노드에 보낼 요청을 CAN으로 브리지에 넘깁니다.
2. 대신 기다림브리지가 요청을 맡아 두고, 곧바로 다음 요청을 받습니다.
3. 재전송노드가 응답하지 않으면 브리지가 정해진 횟수만큼 다시 보냅니다.
4. 결과 보고성공이나 실패만 컨트롤러에 알립니다.

노드끼리 기다리지 않음

한 노드의 요청은 차례대로 처리하고, 다른 노드의 요청은 동시에 진행합니다.

받는 쪽은 언제나 바로 받음

컨트롤러와 브리지는 메시지를 받으면 바로 넘기고, 받는 도중에 다른 응답을 기다리지 않습니다. 그래서 보내는 쪽도 막히지 않습니다.

끝없이 기다리지 않음

모든 기다림에 제한 시간을 둡니다. 한 노드가 멈춰도 전체는 멈추지 않습니다.

연결, 설정, 상태 보고처럼 중요한 메시지는 응답 확인과 재전송을 기본으로 합니다.

큰 데이터는 빠진 부분만 다시 받아, 끝까지 온전하게 받습니다

작은 메모리로 큰 데이터를 받기 위해, 전체를 모으지 않고 받는 대로 저장합니다.
1. 나눠 보내기데이터를 작은 조각으로 나눠 보내고, 빠진 조각만 다시 보냅니다.
2. 순서 맞추기브리지는 순서만 맞춰 넘깁니다. 데이터 전체를 들고 있지 않습니다.
3. 속도 맞추기유선 전달이 밀리면 브리지가 보내는 노드의 속도를 늦춥니다.
4. 온전한지 확인컨트롤러가 SD에 저장하고, 검사값이 맞을 때만 확정합니다.

실패하면 다시 시도

사진은 다음 접속 때 다시 찍어 보냅니다. 끝내 실패하면 에러코드로 알립니다(18쪽).

사례: 사진 장기 시험, 4,283장 빠짐 없음

1분 간격 촬영을 3일 넘게 이어 간 자체 시험에서 사진을 하나도 빠짐없이 순서대로 받았습니다. 별도 시험에서 CAN 버스 에러도 없었습니다.

세 가지 주기로 반응성과 전력을 함께 잡습니다

사용자는 세 값만 정합니다. 노드가 언제 자고 깨고 재고 보낼지는 컨트롤러가 이 값으로 정합니다.

응답 주기

평소에 명령과 설정이 늦어도 이 안에 닿습니다. 길수록 배터리가 오래갑니다.

측정 주기

측정치가 쌓이는 간격입니다. 측정 항목마다 따로 정합니다.

적응형 반응시간

조작한 뒤 이 시간 동안은 노드가 잠들지 않아 바로 반응합니다.

잠드는 시간은 응답 주기와 측정 주기 가운데 짧은 쪽이고, 데이터를 보내는 중에는 잠들지 않습니다. 측정치는 다음에 깰 때 보냅니다. 응답 주기 0(Live)이면 잠들지 않습니다. 끊김은 잠드는 시간의 6배(최소 50초) 동안 응답이 없을 때 판단합니다. 배터리로 최대 3개월 이상 쓸 수 있습니다(계산값, 실측 전).

고정밀 센서로, 오차가 가장 적은 측정 방식을 씁니다

같은 센서라도 측정 방식에 따라 오차가 크게 달라집니다. 실험으로 비교해 가장 정확한 방식을 골랐습니다.

측정 방식에 따른 흔들림(CO2 센서 예)

CO2 센서보드 2대를 나란히 두고 비교한 자체 시험 결과입니다.

깨운 뒤 연속 측정, 안정된 결과만 사용

센서를 깨워 연속으로 재고, 충분히 안정된 뒤의 결과만 기록합니다.

기다리는 동안 노드는 잠듦

센서가 혼자 재는 동안 노드는 잠들어 전력을 아낍니다.

모든 센서에 같은 원칙

센서마다 안정되는 시간을 확인해 같은 방식으로 잽니다.

카메라: 현장을 사진으로 확인하고, AI로 생육을 판단합니다

사진도 측정의 한 종류입니다. 다른 노드와 같은 주기로 깨어 찍고, 같은 방식으로 보냅니다.

기본 기능

  • 주기 촬영과 원격 즉시 촬영
  • 촬영할 때만 켜는 조명
  • 촬영이 끝나면 카메라 전원 차단

사진 기반 AI(개발 중)

사진의 변화를 검출하고, 그 변화량을 생장에 필요한 요소와의 상관관계로 분석하도록 학습해 예측하고 경고하는 AI를 개발하고 있습니다.

단계제공 기능시기
1단계수확 시기 예측, 병해 발생 경고2027년 2분기
2단계온도, 습도, CO2, 양분의 부족과 과다 예측2027년 4분기

시작 분야: 양송이로 학습 데이터를 축적하고 있습니다.

AI 기능은 개발 계획이며, 현재 제공되는 기능이 아닙니다. 같은 기술을 시간에 따라 변하는 다른 관리 대상에도 적용할 수 있습니다.

보드, 센서, 측정 항목을 나눠 교체와 확장에 대비합니다

보드와 센서는 바뀌어도, 화면과 기록의 측정 항목은 그대로입니다.

같은 측정이라도 정밀과 보급형을 나눠 관리하고, 필요에 맞는 센서를 골라 답니다. 보드를 바꾸면 연결선만 새 보드로 옮겨 가고, 정보 단위는 그대로입니다.

원래 보드가 다시 접속원래 측정 항목으로 돌아갑니다. 사용자에게 묻지 않습니다.
하나만 두는 측정 항목(예: CO2)에 새 보드기존 보드가 끊겨 있으면 새 보드가 이어받고, 연결돼 있으면 바꿀지 묻습니다.
여러 개 두는 측정 항목(예: 배지 온도)에 새 보드기존 것을 바꿀지, 새 측정 항목으로 더할지 묻습니다.

상황에 맞게 고르는 다양한 제어 방식

컨트롤러의 주 기능입니다. 직접 연결한 릴레이와 원격 제어기를 같은 방식으로 판단합니다.
방식동작장점단점보완
강제켬과 끔을 직접 지정합니다. 재시작해도 유지됩니다.즉시, 확실하게 동작사람이 풀어야 함정한 시간 뒤 자동 해제
타이머켜기와 끄기를 반복하고, 낮과 밤을 나눠 정합니다.센서 없이 예측대로 동작환경 변화에 반응하지 않음센서 방식으로 바꿈
센서 AI켜는 기준과 끄는 기준만 정하면 정밀 센서 우선, 평균, 추세 판단을 자동 적용합니다.설정이 간단하고, 추세를 보고 미리 대응세부 조정은 기본값을 따름필요하면 센서 수동으로 바꿈
센서 수동기준 센서와 통계, 추세 예측, 최소 유지 시간까지 직접 정합니다.현장에 맞게 세밀하게 조정설정을 이해해야 함센서 AI로 시작해 필요한 것만 조정

통신이 끊겨도 설비는 안전하게 동작합니다

끊기는 곳마다 미리 정한 동작으로 대응하고, 다시 연결되면 상태를 맞춥니다.
끊기는 곳대응다시 연결되면
원격 제어기마지막 상태를 유지하다가 정한 시간(10분, 30분, 1시간)이 지나면 스스로 끕니다.상태를 다시 맞추고, 스스로 껐던 사실을 알립니다.
기준 센서짧은 끊김은 무시하고, 5분을 넘으면 그 설비를 끕니다. 강제 방식은 사람의 명령을 따릅니다.측정치가 들어오면 판단을 다시 시작합니다.
인터넷판단은 컨트롤러가 하므로 자동 제어와 현장 화면은 계속됩니다.웹앱과 휴대폰 알림이 다시 이어집니다.
브리지와 CAN무응답을 감지해 브리지를 다시 시작하고, CAN 오류는 바로 복구를 시도합니다.노드가 자동으로 다시 접속합니다.

끊김은 모두 에러코드와 휴대폰 알림, 기록으로 남깁니다(18쪽). 휴대폰 알림에는 인터넷이 필요합니다.

SD 카드 오류에 여러 단계로 대비합니다

SD 카드는 현장에서 가장 고장 나기 쉬운 부품입니다. 기록이 끊기거나 망가지지 않도록 단계마다 막습니다.
1. 내부 플래시에 먼저최근 측정 기록은 내부 플래시에 먼저 남깁니다. SD에 문제가 있어도 기록이 끊기지 않습니다.
2. 쓴 뒤 다시 확인쓴 내용과 주변을 다시 읽어 비교하고, 달라졌으면 바로잡습니다.
3. 두 곳에 보관두 영역에 함께 기록하고, 한쪽이 손상되면 다른 쪽으로 메웁니다.
4. 고장 감지이상을 감지하면 알리고, 손상이 번지지 않게 쓰기를 멈춥니다.
5. 복구 후 이어 쓰기다시 연결하거나 카드를 바꾸면 검사한 뒤 밀린 기록을 옮깁니다.

공간 자동 관리

사진과 측정 기록의 공간을 나눠 사진이 기록을 밀어내지 않게 하고, 가득 차면 오래된 것부터 정리합니다.

빠른 그래프

기간별 요약을 미리 계산해 두어, 1주일 그래프도 작은 메모리로 바로 보여 줍니다.

백업과 복원

웹앱으로 기록을 백업하고 복원합니다. 재시작해도 같은 기록이 겹치지 않습니다.

체계적인 에러코드로 문제와 원인을 알려 줍니다

스스로 복구할 수 있는 문제는 복구하고, 복구하지 못한 문제는 정해진 코드로 사용자에게 알립니다.
코드분류와 예
E1xxx시작할 때의 메모리 준비
E2xxx요청과 연결: 미연결, 전송 대기열 가득 참
E3xxx사진 받기: 조각 누락, 검사값 불일치
E4xxx촬영: 카메라 실패, 다시 찍기 포기
E5xxx시스템: SD, 브리지, CAN
W6xxx경고: SD 이상 징후, 백업 기한

사용자에게 알리는 경로

  • 현장 화면과 웹앱의 에러 목록
  • 휴대폰 알림(종류별로 켜고 끔)
  • 기록에 원인과 경과, 연속 실패 횟수

먼저 스스로 복구하는 것

  • 통신 실패: 응답 확인과 재전송
  • 사진 실패: 빠진 조각 다시 받기, 다시 찍기
  • 브리지 멈춤과 CAN 오류: 감지 후 다시 시작

현장 화면과 웹앱, 휴대폰으로 확인하고 조치합니다

측정치와 사진을 원격으로 확인하고, 설비를 켜고 끄고, 사건 기록을 봅니다.

컨트롤러 화면

  • 컬러 GUI 터치 화면
  • 한국어와 영어
  • 연결, 측정, 제어, 그래프, 사진, 배터리 잔량

SPA 웹앱

  • iOS, Android 모두 지원
  • 로그인과 세션 관리, 실패 5회면 해당 주소 5분 차단
  • 측정치, 사진, 배터리 잔량, 릴레이 제어, 설정, 백업

휴대폰 알림

  • 웹 세션이 있으면 웹앱으로 전달
  • 없으면 푸시 서비스(ntfy)로 전달
  • 최근 500건을 SD에 기록

에러, 경고, 릴레이, 연결 끊김, SD, 배터리, CAN으로 나누고, 종류별로 끄고 켭니다. 꺼 둔 종류도 기록에는 남습니다.

새 측정 항목을 쉽게 더하는 기반 구조

센서보드 자체가 공용 플랫폼이라 새 센서를 쉽게 장착하고, 장착하면 기록, 그래프, 제어까지 자동으로 이어집니다.
1. 센서 장착공용 센서보드에 새 센서를 달고, 읽기 기능을 더합니다.
2. 측정 항목 정의무엇을, 어디서, 얼마나 정밀하게 재는지 정합니다.
3. 보드가 알림연결할 때 붙은 센서 목록을 보내고, 측정치를 함께 보냅니다.
4. 자동 반영기록, 그래프, 제어 조건, 알림에 바로 연결됩니다.

같은 보드에 센서를 바꿔 달기

필요한 센서로 바꿔 달면, 컨트롤러가 센서 목록을 받아 측정 항목을 만듭니다.
