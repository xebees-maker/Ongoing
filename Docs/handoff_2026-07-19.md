## 오늘 한 일 — Sens 실기 배선 검증(배터리/VIN/LED) + 절전모드 1단계(SCD41 single-shot + PM)

### 1. LOLIN C3 Pico 실기 배선 검증 (COM14 구보드 → COM3 새 보드)

- 플래시 자체가 안 되던 문제 해결 (esptool 직접 호출, `reference_espidf_manual_build_env` 메모리의
  수동 빌드 절차 그대로 사용). 부팅/ESP-NOW 광고 정상 확인.
- SCD41 I2C(GPIO8/10) 미배선 상태에서 통신 실패는 예상된 정상 동작으로 확인.
- **배터리 ADC(GPIO3) 버그 발견 → 원인 파악 → 해결**: 구보드(COM14)는 JP1("BAT_AD") 점퍼가
  납땜 안 돼 있어서 GPIO3가 플로팅 — `batt_mv=5852`처럼 물리적으로 불가능한 고정값이 나옴.
  JP1을 납땜한 새 보드(COM3)에서는 `batt_mv≈4106~4144`로 정상 범위.
- **VIN(USB 감지, GPIO1) 배선 실수 → 재배선 → 해결**: 핀이 하나씩 밀려서 잘못 연결됐던 것을
  사용자가 재배선. 이후 `raw≈3067, mv≈2321` — 문서에 적어뒀던 예상값(USB 연결 시 2300~2350mV)과
  정확히 일치, 안정적.
- **충전 중 Blue LED 상시 점등 기능 추가**: `powered=true`(USB 전원)일 때 배터리% 패턴 대신 계속
  켜짐(`LED_PATTERN_ON`)으로 오버라이드. 처음엔 "센서 이상(burst) > 충전 중" 순서로 짰다가, 사용자
  지적으로 **"충전 중 > 센서 이상 > 배터리%"** 순서로 최종 확정 — 지금 배선 작업 중일 가능성이 높은
  상태라 충전 여부가 더 유용한 정보라는 이유. `Sens/main/sensor_node.c`의 `sample_cb()` 참고.
- USB-Serial/JTAG 특성상 "USB를 뽑는 순간의 값"은 원리적으로 로그로 못 본다는 점 확인(로그 통로
  자체가 USB 케이블) — 대신 업타임 카운터가 끊김 없이 계속 올라가는 걸로 배터리 전원 유지(전원
  뮉스 Q1/D1 정상)를 간접 확인.

### 2. 절전모드 1단계 구현 — SCD41 single-shot 듀티사이클 + Automatic Light Sleep

전체 스펙(`project_sens_sleep_mode_spec` 메모리)에서 이번 패스는 **Sens 쪽만, SCD41만** 범위로
좁혀서 진행(Cntl UI 인터벌 피커 + 허브→노드 설정 push 프로토콜은 다음 작업, 다른 센서 타입도 나중).

- **인터벌 재확정**: 기존 스펙의 5s/10s/30s/1m/3m/10m에서 **5초/15초/1분/3분/10분**(기본 15초)으로
  변경 — 전부 SCD41 single-shot 소요시간(5초)의 배수이면서 1초 베이스 타이머의 배수라 정확히 맞아
  떨어짐(기존 10초/30초는 3초 폴링 타이머와 안 맞아서 최대 2초 오차가 실측으로 확인됨).
- `Common/components/sensor_scd41/scd41.c`/`.h`: continuous 모드(`scd41_read`, 레거시 LCD 콤보용)는
  그대로 두고, `scd41_trigger_single_shot()`/`scd41_poll_single_shot()`/
  `scd41_stop_periodic_measurement()` 신규 추가. `read_measurement_frame()`으로 읽기 로직 공유.
  `scd41_poll_single_shot()`은 "아직 측정 중"과 "측정 끝났는데 읽기 실패"를 `out_ok` 파라미터로
  분리해서 반환 — 처음엔 둘 다 `false`로 뭉쳐서 리턴했다가, 실패 시 다음 트리거가 영원히 안 걸리는
  버그를 스스로 발견해서 API를 고침.
- `Sens/main/sensor_node.c`: SCD41 전용 트리거/폴링 상태머신을 `sensor_read()`에 추가, 1초 베이스
  타이머(`sample_cb`를 SCD41 빌드에서만 3초→1초로 변경)로 15초 사이클 실측 정확도 확보(오차 0).
  DHT22/SHT45/SHT40은 기존 3초 타이머 그대로 — 이번 패스 범위 밖.
- `Sens/main/esp_now_node.c`/`.h`: `SENSOR_DATA` 전송 주기를 컴파일타임 고정(1초)에서
  `esp_now_node_set_data_period_ms()`로 런타임 설정 가능하게 변경, SCD41 빌드에서 샘플 주기(15초)에
  맞춰 호출 — 안 그러면 15초에 한 번만 재는데 라디오는 계속 1초마다 쏴서 절전 의미가 없어짐.
- **Automatic Light Sleep**: `esp_light_sleep_start()` 수동 호출 대신 `esp_pm_configure()`
  (`light_sleep_enable=true`, DFS 없이 min==max=160MHz) 사용 — 기존 esp_timer/ESP-NOW/status_led
  구조를 하나도 안 건드리고 PM 서브시스템이 FreeRTOS idle 구간마다 알아서 잠들었다 깨어남. `sdkconfig`에
  `CONFIG_PM_ENABLE`/`CONFIG_FREERTOS_USE_TICKLESS_IDLE` 활성화, `Sens/main/CMakeLists.txt`에
  `esp_pm` 컴포넌트 추가 필요.

**빌드 검증**: SCD41 single-shot만 먼저 확인(15초 정확) → Automatic Light Sleep 추가 후 재확인,
두 단계로 나눠서 각각 실기 플래시+로그로 검증(문제 생기면 어느 쪽 원인인지 바로 구분되도록). 둘 다
정상 — 배터리/VIN/LED/ESP-NOW 광고 전부 이전과 동일하게 동작, 크래시/워치독 리셋 없음.

**커밋**: `4f49b9e` (scd41.c/.h, esp_now_node.c/.h, sensor_node.c, Sens/main/CMakeLists.txt) —
로컬 커밋만, push 안 함. `sdkconfig`는 `.gitignore` 대상이라 `CONFIG_PM_ENABLE`/
`CONFIG_FREERTOS_USE_TICKLESS_IDLE`는 이 커밋에 안 들어감 — **다음 세션에서 sdkconfig가 새로
생성되면(클린 빌드 등) 이 두 값을 다시 켜야 함**, 안 그러면 PM이 꺼진 채로 조용히 빌드됨.
