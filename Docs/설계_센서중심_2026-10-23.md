# 센서 중심 구조 설계 (2026-10-23)

## 1. 사용자 생각 (출발점)

- 센스 보드에는 어떤 종류의 센서든, 몇 개든 달릴 수 있다.
- 콘에게 의미 있는 것은 **센서(의 종류)**다. 보드는 네트워크 하위 계층처럼 값을 실어 나르기만 하면 된다.
- 센서 식별 번호는 센서 안에 없어도 된다. 종류만 알면 시스템이 번호를 붙여 주면 된다.
- 지금은 센서를 보드 MAC에 묶어 놓았다. 보드마다 센서가 하나여서 그동안 문제가 드러나지 않았을 뿐이다.

## 3. 새 구조

### 3.0 계층 — 보드 · 센서 · 센싱(사용자 결정 10-23, "계층적 이해가 필요")

1. **보드**: 통신만(네트워크 하위 계층처럼). 어느 포트에 어떤 센서가 붙었는지, 어떻게 읽는지를 맡음. 최대 8.
2. **센서**: 보드에 달린 부품. 센서 ID의 단위. 센서 하나가 센싱을 하나 이상 냄.
3. **센싱**: 센서가 내는 값 하나 — 무엇을(온도·습도·이산화탄소·암모니아), 어디를(공기·배지), 얼마나 정확히(정밀·간이).

**사람이 보는 단위는 센싱 값**(사용자 10-23): 센서 하나로 열 개를 재든, 센서 열 개로 하나를 재든 사람에게는 상관없음. 센서 ID는
콘·센스 내부 관리 번호. 사용자 화면에서 보드는 재는 것으로 부름 — "이산화탄소 측정 보드", "온도·습도 측정 보드"(센싱에서 자동, 별칭이
있으면 별칭). 센서 모델 이름(SHT45 등)과 센서 ID는 진단 화면·로그에만.

**용량(기술 제약, 사용자 10-23 — 굳이 크게 잡지 않음)**: 보드 8, 센서 8, 센싱 12. 실제 센싱: 공기 온도·습도 정밀 2, 간이 2,
이산화탄소 1, 암모니아 1, 배지 온도 2(많아야 3~4) = 8~10.

규칙·제한·릴레이 조건은 센서 모델 이름(SHT45, SCD41 …)이 아니라 **센싱**으로 적는다. 예: 공기 온도·습도는 정밀 센싱이 있으면
정밀만 쓰고 간이 센싱은 쓰지 않음(정밀이 없을 때만 간이) — 따라서 "SHT45가 있으면 SCD41은 이산화탄소로만"은 따로 둘 규칙이 아님.

### 3.1 센서 = 시스템 번호

- 센서 하나 = **보드 MAC + 보드 안 자리 번호**로 처음 나타날 때, 콘이 **센서 번호**(의미 없는 16비트 번호)를 붙인다.
- 콘 LittleFS `sensors.bin`에 센서 목록을 둔다. 항목은 번호, 종류, 값 종류들, 이름, 묶음, 지금 붙어 있는 보드·자리, 상태다.
- 센서 종류는 센서 단위다(SHT45, DS18B20, SCD41, SC05 …). "콤보" 종류는 없어진다. 보드는 종류가 아니다.

### 3.2 통신

- 페어링 때 보드가 **센서 목록**을 보낸다. 자리마다 센서 종류와, 그 센서의 값이 채널 배열의 어디에 있는지를 담는다.
- 매 깨움 값은 지금처럼 채널 배열이다. 채널 상한은 지금 5다. 고온 센스는 4채널(온도, 습도, Agar 온도 ×2)이라 그대로 된다.
- 옛 펌웨어 보드(센서 목록 없음)는 "센서 하나, 지금 kind"로 해석한다.

### 3.3 기록·집계

- 측정 기록: 시각, **센서 번호**, chan_type, 값. 지금보다 짧아진다.
- 집계 칸도 센서 번호 기준이다.
- 옛 기록은 버린다(결정 4) — 형식 판이 바뀌면 내부 플래시·SD 통계를 비우고 시작.

### 3.4 이름·묶음·그래프

- 이름(배지 온도 1 등)과 그래프 묶음(온도 묶음 / 가스 묶음)은 **센싱에** 붙인다. 처음에는 센싱 구분(무엇·어디·정밀도)에 따른 기본값.
- 그래프 선 = 센싱 하나.
- 센서 교체 = 새 센서의 센싱이 옛 센싱을 이어받음(결정 2 — 같은 센싱이 시스템에 하나면 자동, 여럿이면 물음). 지금의 자동 사슬("C->F")과
  Agar 고정 3칸은 없어진다.
- 다음 단계로 정해 둔 묶음 그래프(온도: Agar 1·2, 대기 / 가스: CO2, 암모니아)를 여기서 함께 한다.
- 기기가 없는 계열은 그리지 않는다.
- 공기 온도·습도는 정밀 센싱이 있으면 간이 센싱을 숨긴다(기록은 남음).

### 3.5 릴레이 조건(사용자 시나리오) — 그래프 묶음과 다른 개념

**[결정 10-23, 사용자]** 가능한 조합을 모두 내놓지 않고, 간단한 사용자 시나리오만 둔다. 이것이 릴레이 작동의 묶음 정보다.
지금 구현은 분류가 고정되어 있어 사용자가 고를 것이 없다.

| 조건 | 값 |
|---|---|
| 공기 온도 | 정밀 센싱이 있으면 정밀, 없으면 간이. 시스템이 정함 — 사용자 선택 없음 |
| 배지 온도 | 사용자 선택: 배지 온도 센싱 **평균**, 또는 **선택한 하나** |
| 습도 | 정밀 센싱이 있으면 정밀, 없으면 간이(시스템이 정함) |
| 이산화탄소 | 이산화탄소 센싱 |
| 암모니아 | 암모니아 센싱 |

온도는 위 두 가지가 전부다. 여러 온도를 섞는 조합은 두지 않는다.

### 3.6 그 밖

- 그래프 묶음은 그래프를 모아 보여 주는 용도만(연결 대수 제한·릴레이와 무관).
- 주화면 판: 센싱 값 위주, 보드는 "… 측정 보드"로.
- SCD41 보정 버튼: 보드에 SCD41이 있으면(진단·설정 화면).
- 연결 대수 제한: 결정 3.
- `sens_kind_store`(MAC → kind)는 센서 목록으로 대체한다.

## 4. 바뀌는 범위

| 영역 | 내용 | 크기 |
|---|---|---|
| 공통 헤더 | 페어링 메시지에 센서 목록 | 작음 |
| 센스 펌웨어 | 센서 목록 보내기, 고온 센스(SHT45 + DS ×2, 1-Wire 핀 2개) | 중간 |
| 콘 node_hub | 센서 목록 받기·센서 번호 붙이기, 상한 | 중간 |
| 콘 stats_store(2,141줄) | 기록·집계 형식, 옛 기록 옮기기(플래시·SD), 백업 판 | **큼** |
| 콘 ui_main 통계(창·사슬·분류·개괄·그래프) | 센서 기준 + 묶음 그래프 | **큼** |
| 콘 설정 | 센서 이름·묶음 지정 화면(콘·웹) | 중간 |
| 콘 릴레이·주화면·웹 API | 소스·센서 판·응답 JSON | 중간 |
| 웹앱 | 통계·센서 판 표시, 이름·묶음 화면 | 중간 |

걸리는 시간은 근거가 없어 적지 않는다.

## 5. 순서

1. **통신 + 센스**: 센서 목록 메시지를 추가하고(옛 형식도 받음), 고온 센스 펌웨어를 만든다. 콘은 받아서 센서 목록에 기록만 한다. 그래프는 아직 옛 방식이다.
2. **기록·집계**: 센서 번호 기준 형식으로 바꾸고 옛 기록을 옮긴다. 이때부터 고온 센스의 온도 세 개가 따로 저장된다.
3. **그래프·개괄**: 센서 기준과 묶음 그래프로 바꾸고, 사슬과 고정 칸을 없앤다. 이때부터 고온 센스가 그래프에 제대로 보인다.
4. **설정·릴레이·주화면·상한**을 정리하고 `sens_kind_store`를 없앤다.

각 단계 끝에 빌드·플래시·실기 확인을 하고, 다음 단계로 넘어간다.

## 6. 결정할 것

1. **[결정 10-23]** 센서 ID는 **콘이 붙여 센스에 알려 줌**(사용자 — 추상화가 좋음). 센스는 포트별로 ID를 저장(NVS).
   페어링 때 센스가 포트별로 "센서 종류 + 저장된 ID(없으면 0)"를 보내고, 콘은 ID가 없거나 목록에 없는 센서에 새 ID를 붙여
   새 메시지(ID 배정 + ACK, 신뢰 전송)로 알려 줌. 콘 목록을 잃으면 센스가 보낸 ID로 다시 채움. 새 센서는 ID 0이라 새로 받음.
   센스의 일 = 어느 포트에 어떤 센서가 붙었는지, 어떻게 읽는지(사용자).
2. **[결정 10-23]** 센서 교체 — **가급적 자동, 아니면 사용자에게 물음**(사용자). 새 센서(ID 없음)가 나타났을 때 같은 종류의
   센서가 시스템에 하나뿐이고 그것이 응답 없는 상태면 자동으로 이어 받음(이름·묶음 넘겨받기 → 그래프 선이 이어짐). 같은 종류가
   여럿이면 콘 화면·웹에서 "어느 센서를 바꾼 것인지 / 새 센서인지" 물음.
3. **[결정 10-23]** 연결 대수 제한 — 3.0 계층(보드·센서·센싱)으로 정함. 예전 제한은 보드 하나에 센서 하나라 기기 수 = 센서 수였고,
   그래프·화면을 단순하게 하려던 것(메모리 09-28).
   - 보드: 최대 8(통신 노드 한계). 캠은 보드 하나에 카메라 하나라 따로 — 캠 2 그대로.
   - 제한은 **센싱 단위**: 공기 온도·습도(정밀, 간이 각각), 이산화탄소, 암모니아는 시스템에 1개씩. 배지 온도는 제한 없음
     (이미 "평균 또는 하나 선택"). 모든 센싱 제한 없음(조건마다 평균/선택)은 "많이 팔게 되면 그때" 고민(사용자).
   - 범용이 아니니 복잡하게 만들지 않음(사용자). 시스템 전체 센서 용량(배열 크기) 하나만 둠 — 값 확인 필요.
4. **[결정 10-23]** 옛 기록은 **버림**(사용자 "날려도 돼") — 옮기기 없이 새 형식으로 시작. 3.3의 "옛 기록 옮기기"와 5의 2단계
   "옛 기록을 옮긴다"는 하지 않음(형식 판이 다르면 내부 플래시·SD 통계를 비우고 시작).
