## 가장 먼저 확인할 것

- **`git pull` 먼저.** 이 세션 끝에 아래 "Git" 절 커밋 전부 `origin/main`에 push 완료
  (force-push 아님, fast-forward될 것).
- **Cntl/CAM 둘 다 재빌드+재플래시 필요.** 오늘 ESP-NOW 메시지(목록 프로토콜 전면 교체
  포함)와 설정 파일 구조가 바뀜. 재플래시하면 페어링도 초기화되니 재페어링 필요.
- **COM 포트는 항상 이 PC에서 새로 확인.** 마지막 확인값은 Cntl=COM18/CAM=COM5였지만
  PC/USB포트가 다르면 재할당됨.
- **Cntl의 `device_config.bin`(응답성 등 설정)은 이번 세션에 한 번 잘못된 값(2)이 영구
  저장돼 있던 걸 발견하고 고침** — 지금 실기엔 "즉시"로 재적용 완료됨. 새로 플래시하는
  다른 보드/PC라면 설정탭에서 응답성이 의도한 값인지 한 번 확인할 것(파일 기반이라
  재플래시해도 안 지워짐 — 정상).

## 오늘 한 일 요약

자세한 서술은 `한일_2026-08-11.txt` 참고. 핵심만:

1. SLEEP_NOW 타이밍 프로토콜 전면 재설계 — CNTL의 적응형 idle 타이머와 CAM의 웨이크 보고,
   둘 중 나중에 오는 시점에만 CNTL이 슬립을 보냄. CAM은 절대 자율 취침 안 함(5초마다
   SLEEP_NOW_REQUEST 재요청). 응답성 "즉시"(0=Live, 딥슬립 자체 안 함) 프리셋 신설. ERROR와
   별개로 자동소거되는 WARNING 로그 체계 신설.
2. 목록가져오기(3007) 버그 — 프로토콜 근본 재설계로 해결. PHOTO_LIST_COUNT(개수 먼저,
   reliable) → PHOTO_LIST_BATCH×N(최대 64개씩 묶어서 reliable) → PHOTO_LIST_DONE. 파일당
   1건 unreliable 전송 + 사후 SR 복구 방식 완전 폐기. 309개 파일 기준 약 150ms에 완주,
   실기 반복 테스트로 3007 재현 안 되는 것 확인.
3. **응답성 설정값이 "즉시" 대신 조용히 2로 굳어있던 버그 발견+수정** — 원인은 지난 세션의
   `DEVICE_CONFIG_VERSION` 범프(1→2)에 마이그레이션이 없어서, 버전불일치 폴백 때 다른 설정을
   하나라도 Apply하면 응답성 기본값(2)까지 새 파일에 같이 영구 저장돼버렸던 것. 재발방지로
   버전불일치 폴백을 화면에도 표시하게 함. 부수로 촬영주기/응답성/적응형반응 Apply 버튼
   3개가 전부 "부팅 직후엔 표시==저장"이라는 잘못된 가정으로 무조건 비활성화 고정돼있던
   버그도 같이 발견+수정.
4. 목록가져오기 팝업에 "가져오기 명령 전송/목록 수신 중/성공(실패)" 2줄 단계 표시 추가
   (지금촬영 팝업과 동일 구조). 확인용 임시 딜레이는 실기 확인 후 제거, 실제 속도로 복원.

## 오늘 반성할 점 (자세한 배경은 `한일_2026-08-11.txt`와 memory `user_experience_level` 참고)

사용자가 이미 명시한 전제("항상 live로 테스트한다")와 실기 증상이 충돌했을 때, 그 전제를
의심하고 "사용자가 뭔가 안 했을 것"이라는 설명부터 찾은 게 오늘의 가장 큰 실수. 실제
원인은 항상 내가 최근에 건드린 코드 쪽이었음(오늘은 버전마이그레이션 누락, Apply버튼
비활성화 버그 2건 연속). 사용자가 반복된 패턴이라고 강하게 지적 — 다음부터는 사용자 진술을
먼저 사실로 놓고 내 최근 코드부터 감사할 것.
