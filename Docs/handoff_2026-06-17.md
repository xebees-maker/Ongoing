### 배터리 ADC (핵심 — 웹 정보 오류 주의)

| 항목 | 값 |
|------|-----|
| 핀 | **GPIO12 = ADC2_CH1** (IO12 = BAT_ADC, 공식 회로도 핀 테이블 확인) |
| 단위 | ADC_UNIT_2 / ADC_CHANNEL_1 |
| 감쇠 | ADC_ATTEN_DB_12 |
| 분압 | R19=200K (VBAT 상단) + R21=100K (GND 하단), VBAT_DIV=3.0 |
| 캘리브레이션 | `adc_cali_create_scheme_curve_fitting()` — ADC2에서 정상 동작 확인 |

> **주의**: 웹(비공식)에 GPIO1이라는 잘못된 정보가 퍼져 있음. AI 모델 다수가 이를 학습해 GPIO1로 알려줌. 실제는 **GPIO12**가 정답. GPIO1은 배터리와 무관한 floating 핀.

### 전원 회로

```
VBUS ──D1(MBR230LSFT1G)──┐
                          ├── VCC5V
VBAT ──Q1(AO3401)────────┘
        ↑ GPIO14 gate
```

- GPIO14=LOW: Q1 ON → VBAT가 VCC5V 공급 (정상 동작)
- GPIO14=HIGH: VBAT→VCC5V 차단

### 실측값

| 상태 | vADC | VBAT (×3.0) |
|------|------|-------------|
| USB 연결 | ~1357 mV | ~4071 mV |
| 배터리 단독 | ~1355 mV | ~4065 mV |
| VBAT_DIV | **3.0** (이론=실측, 오차 0.1%) |

## 배터리 게이지 구현 (`main/ui_dashboard.c`)

### 동작 흐름

```
bat_adc_init()
  └─ GPIO14=LOW (분압기 활성화)
  └─ GPIO12 floating (pull 해제)
  └─ ADC2_CH1 초기화 + curve fitting 캘리브레이션

bat_sample_cb() @ 1 Hz
  ├─ ADC 읽기 → 11개 순환 버퍼에 저장
  ├─ 진단 표시 갱신 (vADC now / avg / max / n)
  ├─ [첫 샘플] bat_gauge_refresh() 즉시 호출
  ├─ [USB 상태 변경] bat_gauge_refresh() 즉시 호출
  ├─ [N=10] bat_gauge_refresh() 호출 (10초 주기)
  └─ [N<10] bat_display_update(s_last_pct) — 아이콘/색상만 갱신

bat_gauge_refresh()
  └─ 11샘플 이동평균 → vADC mV → VBAT mV (×3.0) → pct
  └─ s_last_pct 저장
  └─ bat_display_update(pct)

bat_display_update(pct)
  └─ usb_serial_jtag_is_connected() 로 충전 아이콘 표시/숨김
  └─ 바 너비, 색상(green/orange/red), % 라벨 갱신
```

### 주요 상수

```c
#define BAT_SAMPLE_MS    1000   // ADC 샘플 주기 1초
#define BAT_SAMPLE_COUNT   11   // 이동평균 버퍼 크기
#define BAT_GAUGE_EVERY    10   // 게이지 재계산 주기 (10초)
#define VBAT_DIV_USB      3.0f
#define VBAT_DIV_BAT      3.0f
#define VBAT_FULL_MV   4200.0f
#define VBAT_EMPTY_MV  3300.0f
```

### 게이지 갱신 타이밍 규칙

| 트리거 | 동작 |
|--------|------|
| 첫 샘플 (n=1) | bat_gauge_refresh() — 즉시 초기값 표시 |
| USB 상태 변경 | bat_gauge_refresh() — 즉시 재계산 |
| N=10 (10초) | bat_gauge_refresh() — 이동평균 재계산 |
| N=1~9 (매초) | bat_display_update(s_last_pct) — 아이콘/색상만 |

> N=10 틱에서는 bat_display_update를 별도 호출하지 않음. bat_gauge_refresh() 내부에서 처리. (구 코드의 "표시 먼저, 계산 나중" 순서 버그 수정됨)

## 추가 작업 (같은 날, 화면 자동 꺼짐 기능 + 장치 B 하드웨어 불량 발견)

### 증상 및 진단 과정

1. "배터리 모드에서 무터치 시 화면 꺼짐" 기능을 추가한 직후, USB+배터리 모두 연결해도 게이지가 0%로 보임
   → 원인: 같은 시점에 `VBAT_DIV`를 검증된 3.0에서 2.0으로 잘못 변경했던 게 진짜 원인 (분압 회로는 R19=200K/R21=100K=3.0이 맞음, 메모리에 실측 기록 있음)
2. 더 심각한 증상: 장치(B)에서 USB를 뽑으면 전원 LED까지 완전히 꺼지고 터치 무반응, 배터리만으로는 재부팅도 안 됨
   → 다른 장치(A)는 같은 배터리로 정상 동작(57%)
   → **동일 빌드(1502d59, 무수정)를 A/B 양쪽에 그대로 플래시**해서 비교 → A는 정상, B는 여전히 사망
   → 멀티미터로 B의 GPIO14(Q1 게이트)=0V(정상), 배터리 전압 정상 인가 확인 → 소프트웨어 변수 제거된 상태에서도 증상이 다름
   → **결론: B는 하드웨어(전원 경로, Q1/AO3401 추정) 불량.** 코드 문제 아님.

### 최종 조치

- 어제 마지막 커밋(1502d59) 상태로 롤백 → 빌드 → A/B 양쪽 플래시로 하드웨어 격리 테스트
- "화면 자동 꺼짐" 기능만 다시 추가 (VBAT_DIV, LittleFS 파티션 변경 등 다른 변경은 포함하지 않음)
- 정상 장치 A(COM9)에 최종 빌드 플래시, 정상 동작 확인
- 커밋 `dbc5d12` "feat: 배터리 모드 화면 자동 꺼짐/켜짐 (10초 무터치)" → origin push 완료

## 추가 작업 (같은 날, DHT22 온습도 + 가스 탭/SCD41 골격)

### DHT22(AM2302) — 완료, 정상 동작 확인

- GPIO1 (OUT, 데이터). 보드 VCC/GND 사용. pull-up 모듈 자체 내장.
- `main/dht22.c/h`: bit-bang 드라이버. `dht22_init()`(입력+내부 pull-up) 1회,
  `dht22_read()`는 5ms간 인터럽트 비활성화하며 40비트 읽고 체크섬 검증.
- 종합 탭 1단=온도(빨강, "23.5 °C" 형식), 2단=습도(파랑, "58 %" 형식),
  좌상단에 12pt 제목("대기 온도"/"대기 습도", Top+12pt), 30pt 값은 단 높이 중앙 정렬.
- 1초 주기로 갱신 (실험 단계; 정식 운영시 2초 이상 권장 — DHT22 스펙).
- **버그였던 것**: 처음 `%.1f`로 포맷했더니 화면에 "f °C"만 찍힘 →
  LVGL이 `LV_USE_BUILTIN_SPRINTF`를 쓰는데 이 경량 sprintf가 `%f`(부동소수점)를
  지원하지 않아서 생긴 문제. 정수 연산(`temp*10`을 정수로 변환 후 `/10`, `%10`)으로
  직접 포맷하도록 수정해서 해결. **앞으로 LVGL 라벨에 소수 표시할 때 절대 `%f` 쓰지 말 것.**

### 가스 탭 + SCD41 — UI는 완성, 드라이버는 미해결

- 기존 "폰트" 탭(3번째)을 "가스" 탭으로 교체하고 2번째로 이동
  (종합 / 가스 / 타이머 순). `ui_font_test.c`는 빌드에서 제외(파일은 남겨둠).
- 레이아웃(`main/ui_gas.c`): CO2 50% + 온도 25% + 습도 25%, 종합 탭과 같은
  스타일(좌상단 제목 12pt, 가운데 30pt 값). CO2는 초록(0x16A085), 온도 빨강, 습도 파랑.
- I2C 배선: 처음엔 터치와 같은 버스(I2C_NUM_0, GPIO41/42 공유)로 시도했다가
  SCD41 통신 중 터치까지 깨짐(`esp_lcd_touch_axs5106 I2C read error` 다발,
  LVGL 틱 주기도 8~10초로 늘어짐) → **전용 버스로 분리**:
  I2C_NUM_1, SDA=GPIO4, SCL=GPIO3 (GPIO2는 DHT22와 겹쳐서 못 씀, GPIO1=DHT22).
- BSP에 `bsp_get_i2c_bus()` 추가(공유 버스 핸들 노출, 지금은 미사용).
- 디버깅 경과:
  1. 처음엔 `start_periodic_measurement`이 항상 실패 → SCD41은 슬립 지원 모델이라
     `wake_up`(0x36F6, NACK가 정상) 명령을 먼저 보내야 한다는 걸 빠뜨렸던 게 원인 중 하나.
  2. `wake_up` 추가 후 `start`는 성공(또는 몇 번 재시도 후 성공)하지만,
     **측정이 실제로 시작된 이후 `get_data_ready_status`(0xE4B8)가 매번
     `ESP_ERR_INVALID_RESPONSE`로 NACK**됨 — 명령 대기 중엔 정상, 측정 중에만 깨짐.
  3. 모듈에 R1/R2(풀업)+C1(작은 캐패시터) 내장 확인 → 풀업 문제는 아닌 것으로 판단.
  4. VBAT 전원이 의심되어 VBUS로 옮겼지만 동일 증상 → 전원 경로 자체보다는
     SCD41이 광음향 측정 시 끄는 전류 스파이크(피크 ~200mA대)를 모듈의 작은 C1이
     못 받쳐주는 것으로 추정 (명령 대기 중엔 전류가 거의 없어 괜찮다가, 측정 중에만
     깨지는 패턴과 일치).
  5. `i2c_master_bus_reset()`로 실패 시 버스 복구 로직 추가 (한 번 멈추면 영구히
     안 풀리는 문제는 막았으나, 측정 중 NACK 자체는 해결 안 됨).
- **결론**: 코드(명령 시퀀스, CRC8, 버스 분리, 복구 로직)는 정상으로 보이고,
  **하드웨어 문제(전원 디커플링 부족)로 판단**. 사용자가 100~470uF 벌크 캐패시터를
  SCD41 모듈 VDD-GND 사이에 추가해서 테스트하기로 하고 보류.
- 진단용 로그가 `scd41.c`에 그대로 남아있음 (`send_cmd` 실패 시 esp_err_to_name,
  `data_ready` status 값, I2C 주소 스캔 등) — 재현 시 바로 추적 가능.
