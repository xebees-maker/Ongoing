== 2026-06-20 작업 요약 (Sens VBUS 감지 + Cntl/Sens 커밋 정리) ==

[ 오늘 삽질한 것들 ]

1. VBUS 분배기 핀 선정에서 두 번 틀림
   - 1차: IO3 추천 — 예전 메모("IO3/4/5 비어있음")만 보고 스키매틱 재확인 안 함
     → IO3 = SD카드 SPI MISO와 공유, 보드에 10kΩ 풀업(R6, 3V3)이 걸려있어서
       분배기 전압이 망가짐. USB 3.1V/배터리 2.7V로 측정 (기대값 2.5V/0.5V와 다름)
   - 2차: IO7 추천 — 이번엔 스키매틱은 확인했지만 펌웨어 코드 대조를 안 함
     → IO7 = sensor-c6.c에서 이미 SCD41_SCL_PIN으로 사용 중이었음
       (확인해보니 IO8도 DHT22_PIN으로 사용 중, 마찬가지로 못 씀)
   - 3차에서야 정답: H1 헤더 노출 GPIO 전부를 스키매틱(풀업/공유버스) +
     펌웨어 코드(define들) 양쪽 다 대조해서 IO5(IMU_INT1, 온보드 IMU와
     공유하지만 펌웨어에 IMU 드라이버 자체가 없어서 실제로는 미사용) 확정
   - 배선 전 전원 OFF 상태에서 IO5-GND 저항 무한대 확인(플로팅 검증) →
     배선 후 전원 ON 상태에서 USB 2.3V / 배터리 0V로 최종 확인

2. 빌드 검증 못 함
   - 이 세션 환경에 ESP-IDF가 PATH에 없어서 idf.py build를 못 돌려봄
   - 코드 리뷰로만 검증, 실제 컴파일 확인은 다음 IDF 터미널 세션에 미룸

[ 잘 찾아낸 것들 ]

1. 사용자가 직접 측정한 두 번의 "이상한 전압"(3.1V/2.7V, 그리고 도움 요청)을
   보고 단순 배선 문제가 아니라 보드 풀업 간섭일 거라 추정 → 스키매틱
   넷리스트에서 R3~R6(10K, IO1~4용) 직접 찾아내서 계산으로 실측값과 대조
   (계산 ~3.17V/2.83V vs 실측 3.1V/2.7V, 거의 일치) → 원인 확정

2. battery_monitor 공유 컴포넌트에 battery_get_adc_handle() 한 줄만 추가해서
   기존 ADC 유닛을 재사용 — 새 ADC 유닛을 또 만드는 것보다 안전하고 Cntl
   쪽엔 전혀 영향 없는 순수 추가로 처리

3. 어제 세션에서 만들어졌다가 커밋 안 된 채 남아있던 Cntl ESP-NOW 허브 작업
   (esp_now_hub.c/.h, ui_nodes.c/.h, 가스탭 제거)을 발견해서 오늘 VBUS 작업과
   분리된 별도 커밋으로 같이 정리함 (섞어서 한 커밋으로 만들지 않음)

[ 반성할 점 ]

- GPIO 핀 추천을 두 번이나 "이전 메모/스키매틱만 보고" 했다가 둘 다 틀렸음.
  사용자가 "신경쓰여서 물어봤는데 일을 여러 번 하게 만든다"고 직접 지적함.
  → 이 보드에서는 GPIO 하나 추천할 때마다 스키매틱(풀업/공유버스)과
    펌웨어 코드(define으로 이미 쓰는 핀)를 반드시 둘 다 확인하기로 함
    (글로벌 메모리 feedback_verify_gpio_before_recommending에 기록)
- 핸드오프/작업로그를 그동안 Cntl/Sens 각자 .claude/memory에 따로 쌓고 있었는데,
  사용자가 Ongoing/Docs 폴더를 만들어서 거기로 통합하라고 지시함 — 오늘부터 적용
