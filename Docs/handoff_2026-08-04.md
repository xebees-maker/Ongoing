# 핸드오프 — 2026-08-04 (PC 이전, 원래 PC로 복귀 예정)

원래 PC(이전 세션이 `handoff_2026-08-03.md`를 남긴 그 PC)로 다시 돌아가서 작업을 이어갈 때 보라고
쓴 문서. Git은 push 완료(`origin/main`, 커밋 `913bf4b`) — 원래 PC에서는 `git pull`만 하면 소스는
다 옴. 이 문서 + 같은 폴더의 `claude_memory_2026-08-04.zip`(Claude 메모리 백업)이 나머지를 채워줌.

## 가장 먼저 알아야 할 것 — Cntl 폴더가 통째로 바뀜

**`Cntl/`가 이제 예전과 다른 프로젝트를 가리킴.** 원래 PC를 떠날 때(8/3) 마지막 개발은 전부
`cntl_incremental_test/`에서 이뤄지고 있었는데(7/31에 커스텀 BSP 포기하고 벤더
`esp_lvgl_adapter` 방식으로 넘어간 뒤), 이번 PC에서 그 사실을 착각하고 옛날에 포기된
`Cntl/`(hand-written `bsp_ws_4_3b` 커스텀 BSP)를 한참 빌드/플래시하다가 흰 화면 먹통만
반복해서 재현했음. git log로 8/3 마지막 커밋(`fc3ce80`)이 `cntl_incremental_test/`만 건드린 걸
뒤늦게 확인하고, 사용자 지시로 **폴더 자체를 정리**함:

- **`Cntl/` = 이제 구 `cntl_incremental_test/`** (실제 개발 중이던 것, 벤더 base). 원래 PC에도
  `Cntl/`이라는 이름으로 이미 있었던 폴더라 혼동하기 쉬움 — **원래 PC로 돌아가면 그쪽의
  `Cntl/`은 이 새 내용으로 덮어써야 함**(git pull하면 자동으로 이렇게 됨, 별도 조치 불필요하지만
  로컬에 미커밋 변경사항이 남아있었다면 먼저 확인할 것).
- **`Cntl_old/` = 예전 그 `Cntl/`**(커스텀 BSP, 포기된 것) — 기록 보존용. 원래 PC의 로컬
  미커밋 변경사항이 있었다면(예: 8/3 이후 `Cntl/`을 더 만졌다면) 이 리네임과 충돌할 수 있으니
  `git pull` 전에 `git status`부터 확인할 것.
- `cntl_incremental_test/`라는 이름의 폴더는 이제 존재하지 않음(git에서도 삭제됨, `Cntl/`로
  통합).

## 오늘 세션 요약

1. **PC 이전 셋업**: git clone, Claude 메모리 이식, ESP-IDF v6.0.2 툴체인 확인(이미 설치돼
   있었음), COM 포트 재확인(CAM=COM13, Cntl=COM12 — 이 PC 기준, 원래 PC에서는 다시 확인 필요),
   새 WiFi 공유기 정보(`hkhome` / `mama0709!`)로 교체.
2. **`Cntl/sdkconfig.defaults`(당시의 옛 `Cntl/`, 지금의 `Cntl_old/`)에 빠져있던 설정 발견/보강** —
   `LV_FS_POSIX_LETTER`, `LV_FS_MEMFS_LETTER`, `LV_USE_TINY_TTF`, `CONFIG_SPIRAM_XIP_FROM_PSRAM`,
   `CONFIG_ESP32S3_INSTRUCTION_CACHE_32KB` 등 — 전부 sdkconfig가 gitignore라 이전 PC 로컬에만
   있고 git에 안 올라와 있던 값들. **결과적으로 이건 죽은 프로젝트(`Cntl_old/`)에 들인 노력이라
   낭비였음** — 지금의 `Cntl/`(구 incremental)은 원래부터 이 값들을 이미 갖고 있었음.
3. **CAM 쪽 sdkconfig.defaults 보강** (이건 유효한 수정, `CAM/`은 안 바뀐 프로젝트) —
   `CONFIG_ESP_CONSOLE_USB_SERIAL_JTAG`(콘솔 REPL 컴파일에 필요), `esp32-camera` 매니지드
   컴포넌트가 git에 파일 2개만 걸쳐 있던 것(체크섬 파일 없어 컴포넌트 매니저가 손상으로 인식)을
   재다운로드 후 패치 2개(`FB_GET_TIMEOUT`, `CAMERA_JPEG_MODE_FRAME_SIZE`) 재적용.
4. **CAM 센서를 OV3660으로 전환**: `CAM/sdkconfig.defaults`의 `CONFIG_CAM_SENSOR_OV5640`을
   `CONFIG_CAM_SENSOR_OV3660`으로 바꿈 — **이 PC에 연결된 실제 CAM 보드에 OV3660이 붙어있기
   때문**. ⚠️ **원래 PC의 CAM 보드가 OV5640이라면 이 설정을 다시 OV5640으로 되돌려야 촬영이
   정상 동작함**(XCLK 24MHz vs 20MHz가 갈려서 잘못 맞으면 촬영 실패/부팅 무응답).
5. **CAM/Cntl 둘 다 빌드 성공 + 실기 플래시 + 부팅 로그 확인** — CAM(COM13), Cntl(COM12) 둘 다
   부팅 로그 깨끗함(WiFi/ESP-NOW/웹대시보드 정상 기동). Cntl 쪽은 화면도 사용자가 직접 확인,
   정상 동작.
6. **컴파일러 불안정 현상 관찰**: `esp_lcd_panel_rgb.c` 컴파일 중 GCC가 병렬 빌드(`-j4` 이상)에서
   재현성 있게 세그폴트(`internal compiler error`, RTL `ira` 패스). `-j1`(완전 직렬)로는 매번
   통과함. 원인 미확정(하드웨어/RAM 불안정 가능성 논의했으나 확정 안 됨, 이 PC에서 계속 빌드할
   경우 `-j1` 유지 권장).
7. **Cntl 폴더 재정리 + 커밋**(위 참고, 커밋 `913bf4b`).

## 원래 PC 복귀 시 체크리스트

- [ ] `git pull` 전에 로컬 미커밋 변경사항 확인(`git status`) — 특히 8/3 세션 이후 `Cntl/`을
      더 만졌다면 새 폴더 구조와 충돌 가능성 있음.
- [ ] **CAM 센서 설정 확인** — 원래 PC의 실물 CAM 보드가 OV5640이면
      `CAM/sdkconfig.defaults`의 `CONFIG_CAM_SENSOR_OV3660`을 `CONFIG_CAM_SENSOR_OV5640`으로
      되돌리고 재빌드/재플래시.
- [ ] **WiFi 공유기 확인** — 원래 PC 환경이 `iptime2.4`(예전 값)인지 `hkhome`(이번에 바꾼 값)인지
      확인. `Cntl/main/esp_now_hub.c`(WIFI_SSID/PASSWORD, 지금은 hkhome로 되어 있음)와
      `CAM`도 마찬가지. 원래 네트워크로 돌아간다면 SSID/PW 다시 교체 필요.
- [ ] **COM 포트 재확인** — 이 PC에서는 CAM=COM13, Cntl=COM12였지만 원래 PC에서는 다시 확인
      (매 세션 재확인이 원칙, [[reference-cntl-cam-com-ports]] 참고).
- [ ] **ESP-NOW 사진 전송 검증 이어가기** — 이게 사실 이번 두 세션(8/3, 8/4) 동안 계속 밀린
      진짜 미완료 작업임. 8/3 세션에서 스트리밍+NACK 재설계까지 끝냈지만 실기 최종 검증이
      "3006인데 잘 들어"(진행은 되는데 결국 타임아웃)에서 중단된 채였고, 오늘(8/4)은 PC
      이전/폴더 정리에 시간을 다 씀 — 이어서 검증 안 됨. **다음 세션은 여기부터 시작**:
      CAM 시리얼(`CKPT:` 로그) 보면서 사진 가져오기 재테스트.
- [ ] **Claude 메모리 이식** — 같은 폴더의 `claude_memory_2026-08-04.zip`을 원래 PC의
      해당 프로젝트 메모리 폴더에 풀 것(경로는 프로젝트 절대경로 기반 자동 생성 — 새 PC
      셋업 때와 동일한 방식으로 실제 생성된 폴더명 확인).
- [ ] **`Cntl_old/`는 그냥 기록 보존용** — 빌드/플래시 대상 아님, 지울 필요도 없음.

  동일시하지 말 것"** — handoff 문서 안의 "Cntl"이 실제로는 `cntl_incremental_test/`를 가리키고

  --stat`으로 최근 커밋이 실제로 어느 폴더를 건드렸는지 먼저 확인할 것.
