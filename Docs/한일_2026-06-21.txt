== 2026-06-21 작업 요약 (ESP-NOW 개발단계 배선 + Cntl 웹/폰트 버그) ==

[ 오늘 삽질한 것들 ]

1. Cntl IP는 받았는데 자간(글자 사이 간격)이 깨짐
   - 6/16에 이미 고쳤던 TinyTTF kerning 버그였음 — managed_components가
     gitignore 대상이라 git에 패치가 안 남아있었고, 오늘 idf.py
     reconfigure/build를 여러 번 돌리는 사이 컴포넌트 매니저가 lvgl을
     다시 받으면서 패치가 통째로 날아갔던 것
   - 같은 두 버그(kerning 엔트리 해제할 때 잘못된 캐시 release, NONE/NORMAL
     조건 반전)가 정확히 재현됨 → 다시 패치
   - 이번엔 재발 방지까지: patches/fix_tiny_ttf_kerning.py를 작성해서
     CMakeLists.txt가 매 configure마다 자동으로(멱등적으로) 재적용하게 함.
     일부러 버그를 되돌려놓고 reconfigure 한 번으로 자동 복구되는지
     실제로 검증함

2. 패치 스크립트 자체가 configure를 죽임
   - 처음엔 경고 메시지에 한글을 넣었는데, Windows에서 CMake가 스크립트
     stdout을 콘솔 코드페이지로 받다가 UnicodeEncodeError로 죽음
   - 원인 파악 후 스크립트 출력을 전부 ASCII(영어)로 교체해서 해결
   - 동시에 .c 파일에 넣은 패치 주석도 한글(em dash 포함)이라 스크립트의
     ASCII 비교 문자열과 안 맞아서 "이미 패치됨" 판정이 틀렸던 것도 발견,
     주석을 영어로 통일해서 정합성 맞춤

3. Cntl 웹페이지("CNTL" 한 줄)가 폰에서 안 뜸
   - httpd_start 로그도 정상, IP도 정상으로 떴는데 폰에서 접속 안 됨
   - 폰 WiFi 대역(2.4G/5G) 불일치 등 네트워크 쪽을 의심해서 확인 요청함
   - 사용자가 재시도하니 정상 접속됨 — 정확한 원인은 특정 못 했음(일시적
     현상이었을 가능성)

[ 잘 찾아낸 것들 ]

1. Sens의 기존 STA/AP Kconfig 패턴(SENS_WIFI_MODE)을 Cntl에도 그대로
   미러링해서 개발단계(같은 공유기 STA 접속) / 양산단계(독자 SoftAP) 전환을
   양쪽 다 갖추게 만듦 — 새로 설계하지 않고 이미 검증된 패턴 재사용
2. 채널+IP 표기를 Cntl "노드" 탭과 Sens LCD/웹 양쪽에 추가해서, 개발단계에서
   "둘 다 같은 채널에 있는지" 눈으로 바로 확인 가능하게 함
3. ESP-NOW broadcast 자체는 처음부터 잘 잡힘 (Cntl이 Sens를 인식) — STA
   개발단계 전환이 깨지지 않고 잘 동작한다는 걸 확인

[ 반성할 점 ]

- gitignore 대상 파일(managed_components)에 패치를 직접 걸어두면 컴포넌트
  매니저가 언제든 다시 받아서 날려버릴 수 있다는 걸 알면서도, 이번에
  반복 작업(idf.py reconfigure를 여러 번) 도중 또 당함 — 처음 패치할 때
  바로 자동 재적용 스크립트까지 같이 만들어뒀어야 했음
- 패치 스크립트를 만들 때 Windows 콘솔 인코딩을 고려 안 하고 한글을 그냥
  찍었다가 configure 자체를 깨먹음 — 빌드 시스템에서 실행되는 스크립트는
  플랫폼 인코딩 가정하지 말고 ASCII로 쓰는 게 안전하다는 걸 다시 확인함
