## 오늘 한 일 요약

자세한 서술은 `한일_2026-08-29.txt` 참고. 핵심만:

1. **Network(WiFi) 설정 기능 신규 구현** — 설정-제어기 판넬에 "네트워크" 행 추가:
   독립(AP)/종속(STA) 드롭다운(모드 전환은 재시작 필요, 팝업 확인), 종속 모드일 때
   우측에 연결된 AP의 SSID 또는 "찾기" 버튼. 예전 `CNTL_WIFI_STANDALONE_AP_TEST`
   컴파일타임 스위치를 `device_config_get/set_wifi_ap_mode()` 런타임 설정으로 승격.
2. **"찾기" 팝업 — 스캔→선택→비번입력→실시간 접속** 전체 구현. 재시작 없이 접속
   전환 가능(esp_now_channelsync의 기존 채널 자가복구 메커니즘이 이미 이걸 지원한다는
   근거로 설계 확정). 비번 보기/숨기기 토글(눈 아이콘), 이전에 접속했던 SSID는 비번
   자동 채움.
3. **다중 네트워크 비번 저장** — 8슬롯 LRU 배열(`sta_credential_t[8]`, PSRAM 할당)로
   재설계, 기존 단일 SSID/비번 필드 대체.
4. **크래시 버그 진단+수정 (연결 성공 직후 리셋)** — 실기 크래시 로그로
   "sys_evt 태스크 스택오버플로우" 확인. 원인: WiFi 이벤트 콜백(2304바이트 스택) 안에서
   `device_config_save()`(784바이트+파일I/O) + 팝업삭제 + 토스트 생성을 전부 동기
   실행. `lv_async_call()`로 LVGL 자신의 태스크로 작업을 미루고, 스택도 6144로 확대.
5. **연결 시도 경합(레이스) 버그 수정** — 틀린 비번 후 재시도가 계속 실패/지연되던
   문제. 원인: 이전 시도의 "실패 후 되돌리기" 재연결이 아직 안 끝난 채 새 시도가
   겹침(`wifi:sta is connected, disconnect before connecting to new ap` 실측 로그로
   확인). DISCONNECTING→CONNECTING 2단계 상태머신 도입, 25초 타임아웃 하나로만 최종
   실패 판정.
6. **"첫 시도만 25초 대기 후 실패" 버그 수정** — `esp_wifi_disconnect()`는 STA가 이미
   idle이면 이벤트를 안 만들어냄 → DISCONNECTING 단계에서 영원히 대기. `esp_wifi_sta_get_ap_info()`(완전연결 여부만 앎) 대신, 모든 `esp_wifi_connect()` 호출 시
   true, 진짜 STA_DISCONNECTED 이벤트 수신 시에만 false로 스스로 추적하는
   `s_sta_conn_in_flight` 플래그로 교체.
7. **"재시도 땐 시도도 안 해보고 즉시 실패" 버그 수정** — CONNECTING 단계의 첫
   disconnect를 곧장 실패로 판정하던 로직 제거. 실제 WiFi 인증은 흔히 재시도를 거쳐야
   성공(성공 로그에도 "Association refused temporarily... comeback time" 확인됨).
   이제 그냥 재시도, 실패 판정은 타임아웃 하나로 통일.
8. **근본원인: 찾기 팝업 여는 시점에 미리 disconnect하던 설계 결함** — 스캔을 위해
   팝업 열자마자 `esp_wifi_disconnect()`를 걸던 게, "이미 같은 AP 선택시 재접속 생략"
   단축경로와 만나서 실제 연결이 끊긴 채 방치되는 버그로 이어짐(사용자가 직접 아키텍처
   교정: "찾기 팝업을 열 때 먼저 걸지마. 비번창에서 연결 누를 때 걸어야 되"). 제거—
   실제 접속 전환 시점(연결 버튼)에서만 disconnect, 이미 `esp_now_hub_test_sta_connect()`
   내부에서 처리됨.
9. **표시 갱신 버그 3건 수정** — 연결 성공/단축경로 둘 다 상단 네트워크 표시가
   갱신 안 되던 것(`refresh_network_right_zone()` 호출 누락), 스캔 리스트에 현재
   연결된 SSID 표시 없던 것("[연결됨]" 태그 추가, `ui_strings` 테이블 사용).
