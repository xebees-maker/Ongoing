[ 한 일 — 실기 크래시 조사 및 수정 ]

9. "콘이 계속 리붓" 신고 — Guru Meditation(InstrFetchProhibited), PC=A0=EXCVADDR로 매우
   낮은 주소, 백트레이스 CORRUPTED. 사용자 단서("Alias만 줬는데") + 재부팅마다 재현되는
   패턴으로 원인 추적: power_relay_set_config()가 호출부 무관하게 항상 configured=true로
   만들어서, Alias 전용 Apply(cb_relay_alias_apply_clicked)도 채널/임계값이 전부 기본값
   (0)인 미완성 설정을 "완료됨"으로 활성화시켜 판정 루프가 그걸 실제로 평가해버림 —
   호출부 책임으로 이관(본 설정 Apply만 명시적으로 true)해서 수정.
10. 방어 가드 추가: chan_type==SENSOR_CHAN_NONE이면 evaluate_relay()가 평가 자체를 건너뜀
    (이미 저장된 잘못된 상태에도 안전).
11. power_relay_task 스택을 4096→8192로 확대(httpd 핸들러가 같은 종류 호출로 스택 부족
    겪었던 전례와 동일 소지).
12. "글 깨짐"(사용자는 한글 유입 의심) 조사 — 실제로는 비트맵 폰트(Montserrat, 영문
    ASCII만)에 없는 특수기호(→/±/°)가 미싱글리프로 깨진 것, 한글 아니었음 — 전부 ASCII
    (->,  +/-, C)로 교체.
13. "드랍다운 화살표와 글씨가 겹침"(반복 지적) 조사 — LVGL 소스(lv_dropdown.c) 직접 확인:
    width_def가 130px(LV_DPI_DEF) 고정, 내용에 자동으로 안 맞춰짐. 옵션 텍스트가 길면
    겹침 — 새 드랍다운들에 명시적 폭 지정해서 해결, 메모리에 기록(반복 실수 방지).
14. "메모리 35K까지 줄었어, 위험해" 신고 — 실측(MEMDIAG 로그): power_relay_start()의
    xTaskCreate()가 8192바이트 스택을 내부RAM에서 할당하고 있었음. xTaskCreateStatic()+
    PSRAM 버퍼(heap_caps_malloc(MALLOC_CAP_SPIRAM))로 교체 — 실측 소모 0바이트 확인
    (esp_lv_adapter의 stack_in_psram=true와 동일 원리). 이후 45초 캡처 동안 내부메모리
    50~65K대 유지, 패닉 없음.

[ 할 일 — 내일 ]

1. Trend window를 "초" 단위 대신 "측정 횟수" 기준으로 재설계 — 지금은 SR 태스크 자신의
   15초 평가주기 기준 최근 T초 창이라, 센서 리포트 주기가 길면(예: 10분마다) 그 창 안에
   새 값이 하나도 없어 추세 계산이 무의미해질 수 있음(사용자 지적). 센서의 실제 측정ID
   (esp_now_hub_node_t.sensor_measurement_id) 변화를 추적해서 "진짜 새 측정값 N개"를
   기준으로 삼는 구조로 손봐야 함.
2. Center/Margin(및 필요하면 다른 숫자 입력들) 컨트롤을 텍스트박스 대신 롤러(lv_roller,
   이미 CONFIG_LV_USE_ROLLER=y로 활성화 확인됨)로 교체 — 필요하면 탭했을 때 팝업으로 롤러
   띄우는 방식. 온도/습도는 소수점 1자리(0.0), CO2는 소수점 없는 정수 4자리(0000).
3. AI Off 상세 섹션의 "Based on(그룹/장치 선택)+그 하위선택(Air Basic/Fine/Agar 또는 장치)

4. Trend 스위치가 Off면 Trend window 입력 필드를 비활성화(지금은 상관없이 항상 입력 가능).
5. 문장 골격 최종 문구로 재작성: "Turn (On/Off) if (Temperature/CO2/Humidity) (Up to/
   Below) [값] +/- [오차] [단위(C 등)]" — 지금의 "If ~ -> ~", "Center:"/"Margin:" 라벨을
   전부 이 형태로 교체.
6. Apply 버튼(본 설정)이 값이 실제로 안 바뀌어도 항상 활성화돼있는 버그 수정 — Alias
   Apply처럼 변경 여부 추적해서 비활성/활성 토글해야 함.

   판넬로 시각적으로 묶고, Apply 버튼 자체는 그 판넬의 우측 상단으로 재배치.
