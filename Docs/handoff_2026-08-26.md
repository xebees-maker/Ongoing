## 가장 먼저 확인할 것

- **`git pull` 먼저.** 이 세션 끝에 아래 "Git" 절 커밋 전부 `origin/main`에 push 완료
  (force-push 아님, fast-forward될 것). 이번 커밋은 지난 세션(`handoff_2026-08-22.md`)
  이후 미커밋 상태로 쌓여있던 작업 전체를 한 번에 묶은 것 — 어제(2026-08-25) 설계한
  CASK 프로토콜 구현 + 오늘(2026-08-26) 실기 검증/버그수정이 한 커밋에 같이 들어감
  (18파일, +945/-1020줄).
- **Cntl/CAM 둘 다 재빌드+재플래시 필수, 반드시 같이.** ESP-NOW 와이어 프로토콜이 이번에
  크게 바뀜 — `ESP_NOW_MSG_WAKE_HELLO`(46)/`_ACK`(47)/`CASK_WORK_NONE`(49)/`_ACK`(50)
  신설, `CHANNEL_PING`/`_PONG`/`DEEP_SLEEP_STATS`/`SET_TIME`/`_ACK`/
  `SLEEP_NOW_REQUEST`/`HUB_RESET` 전부 제거. 구버전 CAM ↔ 신버전 CNTL(또는 반대)은
  서로 못 알아들음. Sens는 로직 변경 없지만 공용 헤더가 바뀌었으니 같이 재빌드는 필요.
- **Cntl 플래시는 앱 파티션만(`0x10000`) 권장** — assets 파티션을 같이 구우면
  `/assets/settings.bin`이 날아감(`project_cntl_assets_partition_reflash` memory 참고).
- **CAM은 딥슬립 중이면 COM 포트가 아예 사라짐(USB-CDC 자체가 꺼짐), 단순 DTR
  플리커가 아님.** 응답성 짧게(예: 10초) 설정된 CAM은 깨어있는 창이 100~200ms 수준이라
  시리얼로 이 틈을 잡아 플래시하는 게 사실상 불가능 — BOOT 버튼 눌러서 강제
  부트로더 진입 후 플래시할 것.
- **COM 포트는 항상 이 PC에서 새로 확인.** 마지막 확인값은 Cntl=COM18/CAM=COM5.

## 오늘 한 일 요약

자세한 서술은 `한일_2026-08-26.txt` 참고. 핵심만:

1. **CASK(CAM+TASK) 프로토콜** — CHANNEL_PING/PONG 하트비트가 페어링 후 사실상
   응답이 안 오던 문제를 조사하다가 더 근본적인 재설계로: CAM이 알고있는 CNTL에게
   직접 WAKE_HELLO를 보내고, CNTL은 CONFIG → 할일(없으면 명시적 CASK_WORK_NONE) →
   SLEEP_NOW 고정 3단 시퀀스로 응답. 실패시 원인 구분 없이 통일된 폴백(브로드캐스트
   디스커버리)으로 재연결. 캠의 핑/통계 타이머, CNTL의 adaptive-deadline 타이머 전부
   제거하고 이벤트드리븐으로 대체.
2. **캠이 실제로 안 자는 핵심 버그** — SLEEP_NOW 상태 리셋이 전송 "후"에 일어나던
   순서 버그(레이스 아님). 전송 "전"으로 이동해서 해결 — 이 수정이 "완벽하게
   동작한다" 확인으로 이어짐.
3. **CASK 전체 완주 타임아웃** — `CASK_TIMEOUT_MS=15000`으로 재설계. "WAKE_HELLO
   판정을 캐스크 전체로 넓힌다"는 프레이밍(새 타이머 개념 아님). SLEEP_NOW가
   유실돼도 무한정 깨어있지 않도록.
4. **CNTL 중앙집중 pending-action 큐** — 노드별 링버퍼로 사용자 명령을 큐잉,
   WAKE_HELLO 응답 때마다 하나씩 CASK에 실어보냄. 여기저기 흩어진
   `require_paired()` 체크 제거.
5. **"통신 중엔 안 재운다" 원칙 + 멀티기기 mac 격리 버그** — 노드별 트랜잭션 진행중
   판정(`esp_now_photo_is_transacting_with`) 신설, 동시에 캡처/전체삭제 진행상태에
   mac 추적이 없어서 한 캠 작업이 다른 모든 노드 슬립을 막던 버그도 같이 발견/수정.
6. **CNTL `esp_now_tx.c` 기존 버그 2건** — 시간기반 재시도 부풀리기(최대 44회) 제거,
   큐 크기 8→32 + 큐풀 시 에러코드(`UI_ERR_TX_QUEUE_FULL`) 추가.
7. **전력로그 AW/SLEPT/I 필드 3건 수정** — AW는 누적치→델타로, SLEPT는 커맨드
   에코값→실측으로, I는 리부팅마다 리셋되던 버그(`RTC_DATA_ATTR` 누락)를 수정. 셋 다
   실기 확인 완료.
8. **실기 검증**: 핵심 슬립/웨이크, 전력로그 3필드, 캠 단독 리셋 후 재연결까지 전부
   확인됨. 보드 발열도 거의 사라짐(딥슬립이 실제로 걸린다는 정성적 확인).
