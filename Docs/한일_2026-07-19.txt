== 2026-07-19 작업 요약 (Sens 실기 배선 검증 + 절전모드 1단계) ==

[ 오늘 삽질한 것들 ]

1. 배터리 ADC(GPIO3)가 말이 안 되는 고정값(5852mV)을 냄
   - 알고 보니 JP1("BAT_AD") 점퍼가 납땜 안 돼 있어서 GPIO3가 완전히 플로팅 상태였음
   - 사용자가 JP1 납땜한 새 보드를 만들어서 COM3에 붙였고, 그걸로 재검증하니 정상
     범위(4106~4144mV)로 나옴

2. VIN(USB 감지) 값이 요동침 (216~623mV로 계속 흔들림)
   - USB가 분명히 꽂혀 있는데 usb=0으로 나오는 모순 발견
   - 사용자가 확인한 결과 배선 핀이 하나씩 밀려서 잘못 연결돼 있었음 — 재배선 후
     raw≈3067, mv≈2321로 안정, 문서에 적어뒀던 예상값과 정확히 일치

3. SCD41 절전 주기가 10초로 설정했는데 실측 12초로 나옴
   - 원인: 기존 3초 폴링 타이머(SAMPLE_MS)로 10초 경계를 체크하니 10000이 3000의
     배수가 아니라서 매번 다음 3초 틱까지 밀림
   - 처음엔 "5초를 6초로 올려서 3의 배수 맞추자"는 얘기가 나왔다가, 사용자가 "그럼
     10초도 3의 배수 아니지 않냐"고 정확히 짚음 → 최종적으로 베이스 타이머 자체를
     1초로 낮추고, 인터벌 옵션도 5초/15초/1분/3분/10분(전부 1초의 배수이자 5초의
     배수)으로 재정리해서 해결. 실측 15000ms 정확히 확인

4. 권한 프롬프트 관련 삽질 (기능 구현과 무관한 세션 이슈)
   - 반복되는 ninja/esptool/시리얼로그 캡처 명령이 매번 확인을 띄워서 사용자가
     자리를 못 비움. git 읽기 전용 명령 허용 목록은 추가했지만, 빌드/플래시류는
     안전상 자동 허용 목록에 넣지 않는 게 맞다고 판단
   - 사용자가 VS Code 확장의 "initial permission mode" 설정을 찾아서 직접 변경 +
     리로드까지 했는데도 여전히 프롬프트가 뜸 — 원인 파악 못 함, 보류하고 계속 진행

[ 잘 찾아낸 것들 ]

1. scd41_poll_single_shot() API 설계 결함을 구현 중 스스로 발견
   - "아직 측정 중"과 "측정 끝났는데 읽기 실패"를 둘 다 false로 뭉쳐서 리턴하면,
     실패 시 다음 트리거가 영원히 안 걸리는 잠재 버그가 생김 — out_ok 파라미터로
     분리해서 해결. 실기 테스트 전에 코드 리뷰로 잡아냄

2. USB-Serial/JTAG 구조적 한계를 정확히 짚음
   - "USB 뽑는 순간의 로그"는 로그 통로 자체가 USB라 원리적으로 불가능하다는 걸
     설명하고, 대신 업타임 카운터 연속성으로 배터리 전원 유지를 간접 확인하는
     대안을 제시

3. Automatic Light Sleep(PM) vs 수동 esp_light_sleep_start() 트레이드오프 판단
   - 수동 방식은 기존 esp_timer 콜백 아키텍처를 통째로 재설계해야 하는데,
     Automatic Light Sleep(esp_pm_configure)은 기존 구조를 하나도 안 건드리고
     PM 서브시스템이 idle 구간마다 알아서 처리 — 리스크 낮은 쪽으로 선택하고
     실기에서 크래시 없이 검증까지 완료

4. 절전모드 전체 스펙 중 범위를 명확히 좁혀서 진행
   - Cntl UI 인터벌 피커 + 허브→노드 설정 push 프로토콜은 다음 작업으로 분리
     (Cntl에 드롭다운 같은 인터랙티브 컴포넌트가 아예 없어서 그 자체가 작지 않은
     작업), 다른 센서 타입도 나중 — 오늘은 Sens/SCD41만 확실히 끝냄

[ 반성할 점 ]

- sdkconfig가 gitignore 대상이라 CONFIG_PM_ENABLE/TICKLESS_IDLE이 커밋에 안 들어감
  — 클린 빌드하면 조용히 꺼진 채로 빌드될 위험이 있음, 핸드오프 문서에 명시했지만
  sdkconfig.defaults 같은 더 튼튼한 장치를 고려 안 한 건 아쉬움
- 세션 중반에 권한 프롬프트 문제 해결을 시도하다가 시간을 꽤 씀 — 결국 못 고치고
  보류했는데, 더 일찍 "이건 제 도구로는 안 되는 영역"이라고 판단하고 원래 작업으로
  돌아갔으면 더 나았을 것
